DESIGN AND FLOW
- Existing house photographs, forest/ivory palette and serif typography retained.
- Stronger hero and clear Find your stay action; booking appears before gallery.
- Mobile places date search before programmes. Calendar is optional, Monday-first,
  correctly split by month, with disabled sold-out days and clear arrival labels.
- No invented programme dates or prices. Missing retreats and failed loading are
  distinct states. Existing property description is retained when configured.
- Dates -> room -> details -> needs -> review; editing dates or guest count clears
  the stale room choice without discarding name, email or personal requirements.
- Full price, deposit and cancellation terms are confirmed by the house; this is
  an enquiry, not instant confirmation or online payment. Wording reflects that.
- Existing email verification, sign-in, My Stay, needs editing and house requests
  remain connected to the same API. No authentication policy change.

LOCAL PREVIEW (Node >=22)
1. npm ci --workspace apps/web-guest --include-workspace-root --ignore-scripts
2. Build with NEXT_PUBLIC_API_URL unset/empty:
   npm run build --workspace apps/web-guest
3. node tools/preview-guest.mjs
4. Open http://127.0.0.1:4318/book/
Sample availability is labelled on screen. For the simulated email gate use
12345678; no real email is sent. Local preview state is memory-only.
Optional environment variables:
  GUEST_PREVIEW_PORT (default 4318)
  GUEST_PREVIEW_SCENARIO=error or sold-out (default available)
  GUEST_PREVIEW_DELAY=10000 (milliseconds; tests late response handling)
Preview is loopback-only and has connect-src 'self' to block live API connections.
