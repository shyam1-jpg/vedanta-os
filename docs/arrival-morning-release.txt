VEDANTA — PRE-ARRIVAL AND MORNING DASHBOARD
Prepared 4 October 2026. Implementation branch: codex/arrival-morning.
Status: local implementation; not deployed by this change.

WHAT IS INCLUDED
- Guest My Stay: review saved details, confirm them, report arrival and see reception acknowledgement.
- Staff Pocket: Morning board is the initial tab. Existing Clock, Tasks, House log and other tools remain available.
- House/admin: /morning/, linked from House log. Uses existing staff authentication and permissions.
- Morning board: confirmed arriving/departing bookings, guest arrival notifications, room status counts, assigned task owners and deadlines, overdue/blocked/unassigned attention view, recent handovers and daily checks.
- Task and assignment buttons lead to the existing task workspace, retaining the existing task editing and approval workflow.

PROFESSIONAL DEFAULTS / SAFETY
- Pre-arrival opens 14 calendar days before a confirmed booking, in Europe/London time.
- An enquiry or provisional/cancelled/completed booking cannot register arrival.
- Overnight arrival notifications are accepted from arrival day until, but not on, departure day; same-day retreats can arrive on their only day.
- A guest must have an authenticated session owning the stay. Staff cannot use a staff token as a guest.
- Current saved details are shown before confirmation. An opaque version check rejects a stale review if another session edits the details.
- Changes to relevant details invalidate confirmation; changes to stay dates invalidate prior arrival milestones.
- Arrival retries preserve the first timestamp. Reception acknowledgement is idempotent and records its staff actor.
- Registration never changes booking status, room status or room occupancy, and never issues keys or door codes.
- No new payment, passport upload, identity verification, email, SMS or external lock integration.
- Staff must complete their existing reception checks, room inspection and key handover separately.
- Arrival board requires group.read. Acknowledgement also requires group.update. Existing handover/task permissions still apply.
- Responses are property-scoped. The morning board excludes private dietary/accessibility/travel text and does not expose emails.
- Morning board refresh is explicit, not push notifications. It shows last refresh and errors rather than treating missing data as zero.
- Booking counts and individual guest arrival registrations are deliberately separate to avoid double counting.
- Room counts describe recorded status only, not a guarantee of room readiness.
- All demo guest/staff data lives only in tools/preview-arrival.mjs and is never seeded into production.
